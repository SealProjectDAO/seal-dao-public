## What shipped

### Code

- **`seal-node` refuses `--dev-faucet` under `--mainnet`**
  (`crates/seal-node/src/main.rs:35-41`). The dev faucet exposes a
  signature-less `seal_faucet` RPC capped at 1000 SEAL / address /
  24 h — fine on a devnet, catastrophic on mainnet (anyone with RPC
  access could mint to arbitrary recipients up to the cap and drain
  the bridge / governance treasuries by repeating the call across
  generated keys). The guard now exits 2 with:

  ```
  error: --dev-faucet refused under --mainnet (unsigned mint to
  arbitrary addresses must never reach a production chain)
  ```

  Pairs naturally with the existing `RpcConfig::testnet` (default
  true) and `seal-node --mainnet` flip introduced 2026-04-22 — the
  flag was already there for address derivation, this just closes
  the mutual-exclusion gap on faucet activation.
